# Research snapshot – 2026-09-19

This file freezes the external Android/Play decisions used for the initial scaffold so Claude does
not need to re-research them on every session. Re-check these sources before a production release or
major dependency/target-SDK upgrade.

## Google Play target SDK

Google Play's current requirement says that from **2026-08-31** new phone apps and app updates must
target **Android 16 / API 36 or higher**.

Source:
- https://developer.android.com/google/play/requirements/target-sdk

Decision for M1: `targetSdk = 36`.

## Android Gradle Plugin / toolchain

AGP 9.4.0 (September 2026) supports API 37 and documents:

- Gradle 9.6.0 minimum/default,
- Build Tools 36.0.0 minimum/default,
- JDK 17 minimum/default,
- maximum supported API 37.

Source:
- https://developer.android.com/build/releases/agp-9-4-0-release-notes

Decision for M1:

```text
AGP       9.4.0
Gradle    9.6.0
JDK       17
compileSdk 37
targetSdk  36
minSdk     26
```

## Android 17 local-network permission

Android 17 / API 37 introduces the runtime `ACCESS_LOCAL_NETWORK` permission for apps that **target
API 37+**. MuPiBox Control deliberately targets 36 initially, so do not add that permission yet.
Treat raising targetSdk to 37 as an explicit migration with permission UI and real-device tests.

Source:
- https://developer.android.com/about/versions/17/behavior-changes-17

## LAN HTTP / cleartext

Android 9+ normally blocks cleartext HTTP for modern-target apps. Network Security Config can opt in,
but broad cleartext should be avoided where possible.

Source:
- https://developer.android.com/privacy-and-security/security-config

MuPiBox-NG currently exposes a dynamic LAN HTTP endpoint. Dynamic private IP addresses cannot be
listed one-by-one in XML, therefore the scaffold opts into cleartext and adds two application-level
guards:

1. `LocalEndpointValidator` accepts only LAN-shaped destinations.
2. `LanOnlyDns` filters DNS answers and refuses public Internet addresses.

Do not add public hosts to the normal box connection flow. Move to HTTPS/pairing when/if the box API
provides a suitable contract.

## Architecture baseline

Use Android's current recommended layered/UDF approach:

- Compose UI,
- screen-level ViewModels,
- immutable UI state / user actions,
- repositories between UI and data sources,
- coroutines/Flow,
- lifecycle-aware state collection.

Reference:
- https://developer.android.com/topic/architecture/recommendations

## Claude Code context strategy

Permanent project rules belong in `CLAUDE.md`; task-specific details should live in focused docs,
rules and skills so recurring sessions do not repeatedly spend context rediscovering the server API.

Repository-specific setup in this scaffold:

```text
CLAUDE.md                         permanent rules / boundaries
.claude/rules/android.md         Android implementation rules
.claude/skills/api-contract/     on-demand API-contract workflow
docs/mupibox-api-current.md      frozen server API facts
docs/claude-prompts.md           copy/paste task prompts
docs/PROJECT_STATUS.md           hand-off state between sessions
.mcp.json                        local-ai MCP entry
```

Anthropic documentation changes over time; re-check the Claude Code docs before restructuring these
files.
